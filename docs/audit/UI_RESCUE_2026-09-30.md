# AsA — UI Rescue Pass (2026-09-30)

Scope note up front: the request that triggered this pass ("FINAL UI RESCUE &
COMPLETE VISUAL REBUILD MISSION") is an 81-point, multi-week product mission
(full visual rebuild + Android device labs + app-store PWA verification +
merged, CI-green PR). One engineering session cannot honestly claim all of
that is done. This document reports **exactly what was inspected, what was
changed, what was verified, and what is not verified**, so nothing here is
overstated.

## BASELINE

Inspected before touching anything: `src/app/**`, `src/components/**`,
`src/lib/**`, `docs/**`, `tests/**`, `package.json`, `next.config.ts`,
`globals.css`. The codebase already carries a prior "cinematic terminal"
design pass (obsidian/brass token system, RTL-aware components, a11y focus
traps, cinematic intro with the exact required Persian welcome line). It is
**not** a first-generation product — but it does exhibit the complaints in
the brief:

- Home stacked a hero **and then four full-width KPI cards** immediately
  below it, plus an always-visible "Requires Attention" panel even when there
  was nothing to report — a status-dashboard first impression instead of a
  product identity.
- `.card` / `.panel` / `.kpi` surfaces were flat: 1px border, no elevation,
  no depth language — "boxes," not a layered scene.
- No Android hardware/gesture **back-button** handling anywhere in the
  overlay system (sheets, drawers, dialogs, the command palette) — back
  would fall straight through to browser history instead of closing the
  overlay first.
- Several `Suspense` fallbacks rendered literal "loading…" text in empty
  space instead of a structural skeleton.
- Bottom mobile nav and rail were functionally solid but visually flat.

## AUDIT

Full inspection covered: routes (`src/app/**/page.tsx`), the shared
component library (`ui.tsx`, `data-state.tsx`, `overlay.tsx`, `chrome.tsx`,
`nav.tsx`), i18n (`lang.tsx`, `lib/i18n/strings.ts`), the market/board/3D
components, the chart shell, AI Clone, PWA registrator, and the test suite
(`tests/*.test.ts`, 92 files). No backend/domain logic was touched — the
truth architecture (LOADING/READY/EMPTY/UNAVAILABLE/STALE/PARTIAL/
ERROR/OFFLINE) was left exactly as implemented; this pass is visual/UX/
interaction only, per the mission's own restriction (§2).

## REBUILD_DECISION

**PARTIAL REBUILD.** The token system, component architecture (Panel, Card,
StatusBadge, Metric, overlays), i18n/RTL, and data-truth contracts are sound
and were preserved. The visual surface language and Home's composition were
reworked; a from-scratch rebuild would have thrown away working, tested
infrastructure for no product benefit.

## VISUAL_REBUILD (what changed)

`src/app/globals.css` — extended the design system rather than replacing it:
- New depth ladder `--e1..--e4` + `--edge-highlight`, applied to `.card`,
  `.panel`, `.kpi` (every page using these primitives now has real elevation,
  hover lift, and an inner edge light instead of a flat 1px box — for free,
  with no per-page changes needed).
- New `.hero-atmosphere` / `.hero-scene` / `.brand-mark` / `.scene` classes:
  a CSS-only ambient layer (drifting radial-gradient orbs + a masked grid
  field), reduced-motion-safe, zero network cost, cheap to composite
  (transform/opacity only).
- New `.stat-inline` for compact horizontal hero stats (replacing a 4-card
  KPI grid with an inline pulse strip inside the hero itself).
- New `.display-1/.display-2` display typography + `.text-gradient-gold`.
- New `.pulse-dot` (one reusable live-heartbeat indicator instead of each
  component inventing its own).
- Rebuilt `.bnav` / `.bnav-item` as a floating, glassy, safe-area-aware
  instrument with active icon lift + glow, and `.rail-item` with a subtle
  hover shift + icon scale.
- New `.surface-glass` / `.card-elevated` / `.editorial-split` / `.hscroll`
  utilities for the "accent, not everywhere" glass rule (§11/§13).

`src/app/page.tsx` (Home) — recomposed per §8/§10:
- Hero is now a `hero-scene` with atmosphere, a dimensional `brand-mark`
  monogram, and an inline pulse strip (TTT state / universe live-count /
  health / advisory boundary) **replacing** the separate 4-card KPI grid.
  One primary object, one primary action, one primary data story — secondary
  telemetry now reads as a strip inside the hero, not four competing cards.
- "Requires Attention" is now a conditional slim banner: it renders **only
  when `attention.length > 0`**. A clean system shows nothing here instead of
  a permanent empty-state card — no dead space, no fabricated status.
- Day Gainers rows gained rank numbers and a magnitude bar (mission §21)
  computed from the same non-null `change24hPct` the label already renders
  (no coalesced-null regression — see TESTS).
- Market3DBox / Orderbook3D / MarketPulse / Opportunities / AI launcher
  sections are unchanged in logic and now inherit the new `.card` elevation
  automatically.

`src/components/chrome.tsx`:
- Desktop rail logo uses the new `brand-mark` treatment; rail header height
  and spacing increased for presence.
- Mobile "More" sheet now groups the remaining nav items **by the same
  `NAV_GROUPS` structure used everywhere else** (Intelligence / Decision /
  Knowledge / Operations) instead of one flat 2-column list — clearer
  hierarchy, same data source (single source of truth preserved).

`src/components/overlay.tsx` — **Android/browser back-button hierarchy**
(mission §54/§38), implemented once in the shared `useOverlay` hook so every
consumer (Dialog, Sheet, Drawer, AdaptiveDrawer, the More sheet, the command
palette) gets it automatically:
- Opening any overlay pushes one `history` entry tagged with its own id.
- A hardware/gesture back press (or the browser back button) fires
  `popstate`, which closes that overlay instead of leaving the route
  underneath it.
- Closing any other way (Escape, backdrop tap, close button, a completed
  action) still just calls `onClose()`; the effect cleanup then pops the
  overlay's own now-unused history entry (deferred one tick so a same-click
  navigation, e.g. a link inside a sheet, can push its own entry first)
  so it never lingers to eat an unrelated later back press.
- Degrades safely if the History API is unavailable (try/catch around every
  call) — Escape/backdrop close still work either way.

`src/app/chart/page.tsx`, `src/app/ai-clone/page.tsx`,
`src/app/brain/strategies/page.tsx` — replaced literal "loading…" Suspense
fallbacks with structural skeletons (chart toolbar+canvas shape, AI Clone
composer+conversation shape, table-row shape) per mission §42/§43. AI Clone's
composer is now a `card-elevated` surface with a focus glow instead of a
plain `Panel`.

`next.config.ts` — added `allowedDevOrigins: ["*.e2b.app"]` (dev-only) so the
sandboxed preview host isn't blocked from the Next.js dev HMR websocket;
production builds don't read this option.

## HOME / MARKET / DAY_GAINERS / ORDER_BOOK / MARKET_PULSE

Covered above. Market3DBox, Orderbook3D and MarketPulse were already

## CHART / AI / AI_CLONE

Chart engine lifecycle/rendering/toolbar was **audited, not rewritten** per

## NAVIGATION / COMMAND_PALETTE / DRAWERS / MOBILE

Back-button hierarchy (§54) now applies uniformly to all of these because
they all route through `useOverlay`. Bottom nav and rail got the visual
upgrades described above. Behavior (focus trap, Escape, tab cycling,
scroll‑lock) was preserved exactly — only augmented, not replaced.

## RTL / LTR / DARK_MODE / LIGHT_MODE

Not changed structurally. `html[dir]`/`html[lang]` logic, the pre-paint
theme/lang boot script in `layout.tsx`, and the light-theme token overrides
were audited and left in place; the new depth/elevation shadows were given
light-theme-appropriate values (soft cool shadows instead of the dark-theme
black shadows) in the same `html[data-theme="light"]` block.

## MOTION / 3D

New atmosphere motion (orb drift) obeys both
`prefers-reduced-motion: reduce` and the app's own `data-motion="reduced"`
attribute (existing convention, reused). No new heavy animation libraries
were added — everything is CSS transform/opacity, composited, and bounded to
a handful of elements (never per-row).

## IMAGES / PWA

Not touched this pass (no imagery changes were necessary or requested beyond
CSS-only atmosphere); PWA registrator/manifest/service worker were inspected
but not modified — no defect was found that this pass's scope covers.

## PERFORMANCE / ACCESSIBILITY

No new dependencies were added to the shipped bundle (`package.json`/
`package-lock.json` are unchanged in this diff). All new visuals are CSS-only
utility classes reused across existing shared components, so the change is
net-neutral to bundle size. Focus rings, `aria-live`, `role="dialog"`, and
keyboard traversal in overlays were preserved unmodified.

## REMAINING_LIMITATIONS

- This is a **partial** rebuild of the highest-leverage surfaces (design
  tokens → Home → navigation → overlays → AI Clone/chart loading shells),
  not the full page-by-page rebuild the 81-point brief describes (Market
  table redesign, Settings "control console" redesign, order-book/market-3d
  visual rework, chart topbar/tool-rail redesign, imagery/hero asset
  generation, etc. were inspected but intentionally left alone this pass to
  keep the diff reviewable and low-risk).
- No real-browser or Android verification was possible in this sandbox
  (see BROWSER above) — the visual result has not been eyeballed by a human
  or a screenshot tool, only reasoned through code + live HTTP + test
  evidence. Please do a visual pass before/soon after merge.
- The back-button history bookkeeping in `overlay.tsx` has one accepted
  edge case: if an overlay is closed via UI in the exact same tick as an
  unrelated client-side navigation, its history marker may occasionally
  survive as one extra harmless back-step (never a stuck state) — documented
  in the code comment at the cleanup site.
